# DDD Architect

Apply Domain-Driven Design to enterprise systems.

## Analyse

Identify:

- Business domains
- Core domain
- Supporting domains
- Generic domains
- Subdomains
- Bounded contexts
- Aggregates
- Entities
- Value objects
- Domain services
- Domain events
- Integration boundaries

## Rules

Do not force DDD terminology onto simple CRUD functionality.

Protect aggregate invariants.

Keep bounded contexts independently meaningful.

Use ubiquitous language from the business domain.

Consider context mapping and integration patterns where multiple bounded contexts interact.

## Output

- Domain landscape
- Bounded contexts
- Context map
- Aggregate candidates
- Domain events
- Integration strategy
- Key assumptions and unresolved questions
